## 7. Registration contracts and state machine

**States** — `RegistrationKind` = `unregistered | demoPending | registered | rejected | revoked`, each materialized as
a `sealed class RegistrationStatus` subclass in `registration_status_states.dart`, carrying its own `toMap()` and a
`userLabel` that names the simulation out loud (e.g. `Registered.userLabel` at `:74-75`: *"Registered (DEMO —
simulated locally; the phone never met another device.)"*).

**Refusals** — `RegistrationRejectReason`: `code-format`, `code-expired`, `code-mismatch`, `code-already-used`,
`attempts-exceeded`, `duplicate-device`, `transport-missing` — deliberately separated so a screen can distinguish
"you typed it wrong" from "this build cannot pair at all".

**Transition table** (`registration_transitions.dart:27-55`; anything unlisted is refused):

| From \ To | unregistered | demoPending | registered | rejected | revoked |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `unregistered` | — | yes | no | yes | no |
| `demoPending` | yes (clear) | yes (retry, higher attempt count) | yes | yes | no |
| `registered` | yes (full local reset) | no | — | no | yes (local unpair) |
| `rejected` | yes (clear) | yes | no | yes (further failed attempt) | no |
| `revoked` | yes | yes | **no** | no | — |

`revoked → registered` is impossible by design: a revoked device must run a fresh attempt. Illegal moves return
`Err<RegistrationStatus>(ValidationFailure)` with a stable `field: 'registration_transition'` and a `detail` that
names both kinds and the allowed set (`:80-91`) — never a throw, never a silent no-op, matching the `Result`
vocabulary of `haven_core`. `reachable()` (`:97-107`) answers the multi-step question so "not yet" is
distinguishable from "never".

**Expiry** — injectable `Clock` from `haven_core` (default `systemClock`); `DemoPending.isExpiredAt(at)` /
`remainingAt(at)` (`:40-43`) take the instant as a parameter, so boundary tests never sleep. TTL is the DEMO's
5 minutes (D-3 ii), recorded with its provenance in `demo_registration_policy.dart:11-21`.

**Duplicates & unpairing** — `Revoked.stableLocalId` is retained (`:120-122`) precisely so a relaunch cannot mint a
second identity for the same device; `duplicate-device` is the typed refusal. Unpairing is *local* unpair and is
labelled as such in both the state label and the audit kind `unpaired-locally`.

**Audit rows** — `RegistrationAuditRow` (`registration_audit.dart`) holds event kind, an injected-clock timestamp,
`codeDigits` (**length only, never content**), optional reject reason, attempt count and note. Nine
`RegistrationAuditKind` values cover `code-submitted … state-restored-from-malformed`, including
`cross-device-blocked`. The doc comment at `:31-40` states the contract rule it implements
(`docs/implementation/00-app-contract.md:108-109`).

**Persistence** — `LocalRegistrationRepository` writes **one additive `registration` section** inside the child's
existing `childLocalState` document (`registration_repository.dart:23-43`; the additive section key `registration` is declared at `:43`) — same file, same writer, re-read-before-
write discipline; **no new table, no new database, no backend**. A damaged section recovers to `Unregistered` with a
recorded reason; a damaged *document* is a typed failure and is never silently reset.

**Blocked outcomes** — `BlockedRegistrationService` is the seam the contract registers by default: every cross-device
method answers `blocked(...)` naming `missingTransport` and `missingRevocationLane` verbatim
(`blocked_registration_service.dart:32-41`). The local DEMO state machine never claims a remote participant
(`DemoPending.userLabel`: *"DEMO — waiting on this device only. No parent phone has been contacted."*).

**Reachability** — nothing in `features/registration` is wired into a route, binding or screen: grep for
`features/registration|RegistrationBindings|RegistrationController` over `apps/haven_child/lib/main.dart` and
`lib/app/` returns no matches (this pass), and `RegistrationStatusLabel` is imported only by its own defining file.
The rebuilt child APK is byte-identical to the pre-Stage-2 artifact (section 19). This is the intended Stage-2 shape
— contracts and tests, not a shipped pairing UX.

## 10. Kotlin/Dart cross-language agreement test — design, results, drift proof (workstream C)

**Authoritative source**: `android_native/child_services/platform_bridge/BridgeContract.kt` (channel `CHANNEL`
`haven.dev/child_device_state`, method `METHOD_READ_ALL` `state.readAll`, four `KEY_*` envelope keys, three
`ERROR_*` codes — read this pass, lines 12-31), plus `DeviceStateReader.kt` (5 section names),
`HavenBridge.kt` (5 registered readers), `OsAnswers.kt` (`TrackedPermission` wire keys).

**Mechanism** — the tests parse the Kotlin **off disk** at run time and compare per item:

- Parent: `cross_language_key_agreement_test.dart` reads the four Kotlin files (`androidNativeRoot()` walks up from
  the CWD and *throws* rather than skipping if the tree is missing, `:131-145`), extracts `const val NAME = "value"`
  pairs, and checks them against the Dart mirror — channel/method against `DeviceStateChannel` constants, envelope
  keys and section names against the literals the Dart decoders actually index (`envelope['…']`, `areaReading('…')`),
  permission wire keys against `device_state_card.dart`'s `answerFor('…')` calls.
- Child: `child_native_key_agreement_test.dart` + `kotlin_source_lane.dart` do the same for
  `ChildNativeContract.entries`, in **both directions** (every mirror entry must match Kotlin; every Kotlin constant
  must appear in the mirror), and assert the registry is complete with unique ids.
- Anti-vacuity: both suites start with a parse-shape test (`hasLength(9)` bridge constants, `hasLength(5)` sections,
  5 readers, 5 permission keys, 4 Dart envelope keys) so a broken regex disarms nothing silently.
- Error codes are the one family the parent Dart lane passes through opaquely, so their Dart-side mirror is the table
  at `cross_language_key_agreement_test.dart:91-103`; that is still a real check because the Kotlin side is read from
  disk, never from the test file.

**Drift detection proven empirically** (full log `_scratch/p3_stage2/drift/drift_experiment.md`): with
`KEY_API_LEVEL` temporarily changed to `"apiLevel_DRIFT"` in the Kotlin file —

- parent suite → `+6 -1 Some tests failed`, message naming `KEY_API_LEVEL = "apiLevel_DRIFT" in BridgeContract.kt but
  the Dart decoders no longer index that string`;
- child suite → `envelope.apiLevel [E]  Actual: 'apiLevel_DRIFT'`.

The constant was then reverted and verified: pre- and post-`sha256sum` both
`ffa1f71439955c3ebe8719b29bb8a0ee797e3a0a375ab01f5e087880f0b54018`, `git diff -- android_native/` empty, and both
suites green again (7 and 36). So the claim "these tests detect contract drift" is evidenced, not asserted.
**Limit stated**: exactly one mutation was exercised; the add/rename-detection cases rest on the count/set
assertions, which pass but were not each separately mutation-tested.
